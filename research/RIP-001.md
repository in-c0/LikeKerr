# RIP-001 — Can another athlete follow a footballer's match-effort rhythm?

**Status:** Implementation underway  
**Milestone:** M001 — Run one real football match

## Question

Can a recorded footballer's locomotion trace be transformed into a personalised physiological target that another athlete can follow on an automatically controlled treadmill, with useful real-time HR Sync feedback?

## Assumptions we are willing to build on

These are not treated as established findings.

- **H1:** Football locomotion data can be transformed into a useful player-effort rhythm.
- **H2:** Relative player effort can be mapped to another athlete's personalised target HR trajectory.
- **H3:** HR plus treadmill speed/incline can keep the user meaningfully synchronised with that trajectory.
- **H4:** Following a real match-derived rhythm is useful and engaging enough to repeat.

## M001 implementation

```text
player match trace
        ↓
relative effort E_p(t)
        ↓
athlete calibration + selected intensity
        ↓
personalised target HR(t)
        ↓
closed-loop workload controller
        ↓
independent safety guard
        ↓
treadmill speed / incline
        ↓
live HR response
        ↓
HR Sync + session telemetry
```

The same session telemetry is sent to the XR client, but the XR client has no actuator authority.

## Quantities

### Measured
- user HR;
- treadmill-reported speed/incline where available;
- timestamps;
- connection/dropout state;
- user stop events.

### Derived
- selected-player speed and acceleration from the match trace;
- player effort estimate `E_p(t)`;
- personalised target HR;
- HR response lag estimate;
- HR Sync score;
- session workload metrics.

### Assumed / configured
- athlete HR calibration envelope until formally measured;
- machine speed/incline/acceleration envelopes;
- M001 effort-transform parameters;
- M001 physiological response parameters.

## HR Sync v0

The first score is intentionally transparent rather than physiologically sophisticated:

1. smooth target and observed HR over a configurable window;
2. compensate for a configurable/learned HR response lag;
3. compute absolute target error normalised by the athlete's calibrated HR reserve;
4. map that error to a 0–100 score;
5. report current-window and whole-session Sync separately.

A later model may replace this score if experiments show it is misleading.

## Predeclared M001 engineering success criteria

M001 succeeds as an engineering vertical slice if:

- one legal/open match-derived player trace replays end to end;
- a real HR sensor can stream continuously into the controller;
- the deterministic treadmill simulator follows safe commands;
- one real controllable treadmill can later be enabled behind the same adapter contract;
- target HR, observed HR and HR Sync are visible and logged;
- actuator requests cannot bypass the safety guard;
- XR loss has no effect on treadmill control.

These criteria **do not** establish medical safety, sports-performance benefit, physiological equivalence to the professional player, or equivalence to overground football.

## What would falsify/revise the concept?

Examples:

- match locomotion produces an effort target too noisy or uninformative to train against;
- HR dynamics are too slow for the resulting rhythm to feel meaningfully connected to match play;
- closed-loop treadmill control requires workload changes that are uncomfortable or unsafe;
- HR Sync rewards behaviour that does not correspond to sensible training;
- users prefer ordinary match-derived intervals to continuous synchronisation;
- VR materially worsens locomotion/balance without enough experiential benefit.

Any of these results changes the product rather than being hidden as a failed build.

## Current result

The platform-neutral M001 control-core baseline now implements:

- relative-effort to target-HR planning;
- 50/80/100/120/Adaptive intensity contract;
- HR Sync v0 scoring primitive;
- deterministic safety-envelope clamping;
- stale-HR recovery behaviour;
- user-stop override;
- deterministic treadmill simulation.

The remaining pivotal M001 work is a real match-derived player trace, real HR input, and end-to-end session execution.
